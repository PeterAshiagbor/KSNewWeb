Security

5 findings

The core access control is sound — verified: RLS on both tables, no anon read anywhere, the allowlist policy is self-row-only (no email enumeration), the dead SECURITY DEFINER function is revoked from all client roles, and the perks linkifier cannot emit non-http(s) URLs. What remains is abuse- and config-risk, not a data breach.

MEDIUMabuse / dos

Open signup: anyone can trigger magic-link emails and create auth users

Perks.tsx:56–61 calls signInWithOtp without shouldCreateUser: false (Supabase defaults to true; absence verified by grep). Anyone with the public site — or the committed anon key — can fire sign-in emails at arbitrary addresses and create unbounded rows in auth.users. The allowlist still blocks the data, so this is spam/quota-burn, not a leak.

FixPass options: {shouldCreateUser: false}; enable Supabase Auth rate limiting / CAPTCHA.

MEDIUMconfig-dependent

RLS trusts the JWT email claim unconditionally

Every gate reduces to lower(auth.jwt() ->> 'email') = lower(allowlist.email). Safe for magic-link — but if the project ever enables password signup with email confirmations off, an attacker can register an allowlisted address with their own password and walk straight through.

FixConfirm “Confirm email” is enforced project-wide; disable unused auth providers.

LOWhygiene

.env committed and unignored; real PII in .lovable/plan.md

The anon key and project URL are publishable by design, but they feed the abuse above, and the next value added to .env gets committed too. .lovable/plan.md holds a real user’s email, allowlist status and sign-in history — and stays in git history if the repo is public.

FixGitignore .env and .lovable/; delete plan.md; commit a .env.example.

INFOverified safe

Checked and clean

No XSS in renderHow() (scheme-guarded, React-escaped, DB write-locked); no email enumeration; dangerouslySetInnerHTML only in the unused shadcn chart; no external scripts. Google Fonts has no SRI and there is no CSP — hardening, not urgency.

Runtime correctness

8 findings
HIGHrace condition

Perks sign-in can hang on “Verifying access…” forever

Perks.tsx:310–368 — the verify effect depends on the session object, and its cleanup sets cancelled = true. On magic-link redirect, onAuthStateChange and getSession() each deliver a different object identity for the same user: run #1 starts the RPC and sets the user-id ref, the second session re-fires the effect, its cleanup cancels run #1 mid-flight, and run #2 early-returns because the ref already matches. The user who just clicked their sign-in link sits on a spinner with no retry control.

FixDepend on session?.user?.id; reset the ref in cleanup when the check didn’t complete.

HIGHdead funnel

The apply funnel dead-ends at href="#"

Apply.tsx:193–200 — the page’s primary CTA, “Join the waitlist”, scrolls to top and joins nothing (the code comment admits the form embed is missing). Prospective applicants cannot apply. All ten backer LinkedIn links are likewise "#" with target="_blank" — each opens a new tab of the same site.

FixEmbed the form (or a mailto) now; remove the backer anchors until real URLs exist.

HIGHnavigation

No scroll reset on route change

React Router v6 doesn’t reset scroll and no ScrollToTop exists. The main entry to /apply is the envelope at the bottom of the home page — users land on Apply scrolled deep into the page. scroll-behavior: smooth on html means the fix must use behavior: "auto" or it animates.

HIGHfragile deploy

Missing env vars white-screen the whole site, not just Perks

integrations/supabase/client.ts:5–11 runs createClient at module scope, and Perks is statically imported by App.tsx — so it executes on every page load. Deploy anywhere that doesn’t inject VITE_SUPABASE_URL and the homepage throws during module evaluation. It works today only because .env is committed.

FixReact.lazy the Perks route (also the biggest bundle win), or validate env at startup.

MED · LOW4 smaller items

Smaller, still real

Flip-card content unreachable on touch (hover-only; see the accessibility twin below). NotFound links home with <a href="/"> — full reload, replaying the 2.5s gate; should be <Link>. Loading digits reshuffle mid-fade — Math.random() in render re-rolls ~40 digits when fade-out begins. SideNav goes stale past “Apply” (EmailCTA has no id) and the marquee loop has a ~5px seam per cycle (3× copies vs ⅓ translate).

Explicitly checked, not bugs: the stat-strip border ternaries, the {...fadeUp} spread ordering, flip-card CSS specificity, vitest include pattern.

Performance

7 findings

Measured, not estimated. First-visit payload on /: ~8.9 MB of media and JS, delivered behind a deliberate 2.5-second curtain.

5.6 MBcritical

Hero video: ~8.9 Mbps bitrate for a blurred background loop

public/hero-bg.mp4: 1920×1072, 5-second loop, 5,586,980 bytes. No poster, default preload="auto" — downloads immediately on every visit, competing with JS and fonts. On iOS Low Power Mode autoplay is refused and the hero shows nothing but the overlay.

FixRe-encode 720p CRF 28–32 (→ 400–800 KB, ~90% smaller); add poster + preload="metadata"; show the poster under reduced motion.

2.8 MBcritical

A photographic PNG as a section background, under a 40% overlay

src/assets/backers-bg.png (1071×1920) — wrong codec by ~10× for photographic content whose fine detail the overlay hides anyway; loads eagerly despite sitting several viewports below the fold.

FixWebP/AVIF q≈60 → 150–300 KB; lazy-apply via IntersectionObserver.

2.5 sself-inflicted

The loading gate is a designed-in Core Web Vitals “Poor”

A pure setTimeout(2500) uncorrelated with any real loading: it delays fast connections without helping slow ones, pushes real-world LCP to 4–6s+, and the hero’s entrance animations finish behind the overlay — they are never seen.

FixGate on actual asset readiness capped ≈800ms, or make it first-visit-only via sessionStorage.

727 KBone chunk

No code splitting; Supabase and dead react-query ship to every visitor

All five routes statically imported, zero React.lazy. The build confirms one 727 KB chunk (226 KB gz) — Vite prints the warning itself. @tanstack/react-query is instantiated in App.tsx, yet zero useQuery/useMutation calls exist anywhere: ~13 KB gz of dead provider.

FixLazy-load Perks (Supabase) and Fellows; delete react-query outright.

552 KB3 smaller items

Logos, images, fonts

552 KB of logos rendered at ≤48px (partner PNGs up to 800×800 shown at 28–40px; resize + WebP → ~55 KB). The marquee renders 8 logos as 72 permanently-animating DOM nodes (2× duplication suffices; pause off-screen). Zero width/height, loading="lazy" or srcset attributes exist on any image (CLS + eager downloads). Six render-blocking font files; and ApplyCTA uses font-serif with no serif configured — the envelope letter silently renders in Times.

Accessibility

9 findings
CRITICALwcag 2.1.1

Hover-only flip cards exclude keyboard and touch users entirely

The alumni card back — description and stage badge — is revealed only by :hover on a plain <div>: no tabindex, no role, no key handler. Most of a marketing site’s audience is on mobile; they never see this content.

FixMake the card a <button aria-expanded>; flip on focus and click as well as hover.

CRITICALorphan routes

Nothing links to /fellows or /perks — on any device

Verified by grep: the two routes exist only in App.tsx. SideNav is hidden md:flex (mobile has zero navigation UI) and only scrolls homepage sections anyway. Both pages are reachable solely by typing the URL — which also makes them invisible to crawlers (see SEO).

FixReal header/footer navigation, all breakpoints. The Footer currently holds only a mailto.

HIGHwcag 2.3.3

prefers-reduced-motion respected nowhere

Zero hits across the codebase (verified): framer-motion on every section, three infinite marquees, flip cards, the matrix loading screen, autoplaying video, smooth scroll.

Fix<MotionConfig reducedMotion="user"> plus one CSS media block killing marquee/matrix animations and smooth scroll, and pausing the video.

HIGH4 Hz flash

The loading screen flashes at 4 Hz with no accessible semantics

matrix-flicker runs at 0.25s — four opacity flashes per second, above the 3-per-second general-flash threshold (the small dark-red area mitigates, but on mobile the grid is a meaningful viewport fraction). No role="status"/aria-busy; focus is not trapped, so keyboard users can Tab into the hidden page underneath.

4.00:1computed ratios

Contrast: white-on-red fails AA; two greys fail outright

White on red = 4.00:1 — fails AA normal text; used on the 10px “APPLY” seal and both primary buttons (darken to ≈#E60000 or use near-black text). muted-foreground/50 = 2.27:1 (“London, UK”) and placeholder at /60 = 2.78:1 both fail. For the record: primary red on background = 4.95:1 — passes AA, though pure red collapses for protanopia. Backers’ glass cards sit on a photo — contrast unverifiable by design; give them an opaque ground.

MEDIUM4 smaller items

Cursor, nameless links, nesting, headings

Custom cursor forced on * — links never show pointer, inputs never show the I-beam, OS cursor-size settings are ignored (scope to body, restore interactive cursors). Ten icon-only backer links with no aria-label (Fellows does it correctly — copy it). A <button> nested inside a <Link> in the envelope CTA — invalid HTML; make the seal a <span aria-hidden>. The home page has no <h1> (the brand is an img, the tagline a <p>); Fellows and Perks skip h1→h3. Plus: Perks’ collapsible lacks aria-controls, the decorative video isn’t aria-hidden, and default focus rings are near-invisible on #0A0A0A.

SEO

5 findings
HIGHcrawlability

Client-only SPA behind a fake loading gate; two orphan pages

The served HTML is an empty <div id="root">; the 2.5s timer degrades the render snapshot for Googlebot and real users alike, and non-Google crawlers (most AI and social crawlers) see nothing. With no internal links and no sitemap, /fellows and /perks are effectively unindexable. The site is fully static content — trivially prerenderable.

FixPrerender all four routes (vite-ssg or a prerender plugin); add navigation + sitemap.xml.

MEDIUM3 smaller items

Meta, OG image, sitemap

One set of meta tags for all routes — no head management anywhere, so /apply, /fellows and /perks all present the homepage title and description in search results and shares; no canonical, no og:url. The OG image lives in the site-builder’s bucket (gpt-engineer-file-uploads) — not brand-controlled, can vanish, and leaks the tool. No sitemap.xml; robots.txt has no Sitemap: line. The marquee also announces each partner logo up to 24 times to screen readers — mark the rows aria-hidden with one visually-hidden partner list.
