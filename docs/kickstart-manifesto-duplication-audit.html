Every duplication in the manifesto site

A full pass over all 145 files. Nothing is byte-for-byte copied — no two files share a hash. The duplication here is structural: a vendored component library almost none of which is used, one animation block pasted nine times, one access rule written into the database three different ways, and a set of facts about Kickstart that are typed out in four places and no longer agree with each other.

Dead weight shipped with the repo

10 findings

This is the single largest item. The project was scaffolded from a full shadcn/ui install and the unused 92% of it was never removed, which also drags in three quarters of the dependency list.

3,764 LOC 45 files

45 of the 49 shadcn/ui components have no importer anywhere in the codebase

Only tooltip, toast, toaster and sonner are referenced outside src/components/ui/ — and all four are referenced only by App.tsx, which mounts them without ever using them (see next two findings). Everything else — accordion, calendar, carousel, chart, command, dialog, form, sidebar, table, select, and 35 more — is unreachable code.

FixDelete every file in src/components/ui/ that nothing imports. Re-add individual components with the shadcn CLI if and when a page actually needs one.

×2 both unused

Two complete toast systems are mounted, and no code raises a toast

App.tsx renders both <Toaster /> (the Radix stack) and <Sonner />. They are two competing implementations of the same feature. Grepping the whole of src/ outside the toast files themselves returns zero calls to toast() or useToast().

  • src/App.tsx:39–40
  • src/hooks/use-toast.ts (186 LOC)
  • src/components/ui/toast.tsx (111)
  • ui/toaster.tsx (24)
  • ui/sonner.tsx (27)

FixRemove both. If toasts are wanted later, pick one — Sonner is the lighter of the two — and drop the other permanently.

×1 re-export shim

A three-line file exists only to re-export another file

src/components/ui/use-toast.ts imports useToast and toast from @/hooks/use-toast and immediately re-exports them. It creates a second import path for the same two symbols, and nothing imports it.

FixDelete the file. (Moot once the toast system goes.)

28 LOC unused

NavLink.tsx reimplements react-router's own NavLink, and nothing uses it

It is a compatibility shim that restores the React Router v5 activeClassName / pendingClassName API on top of the v6 render-prop API — duplicating a library the project already depends on. No file imports it.

FixDelete. Use NavLink from react-router-dom directly if a nav link is ever needed.

19 LOC orphaned by proxy

useIsMobile is consumed only by the unused sidebar component

src/hooks/use-mobile.tsx has exactly one importer: ui/sidebar.tsx, which itself has none. Every responsive decision in the actual site is made with Tailwind breakpoints instead.

FixDeletes automatically with the sidebar component.

37/51 deps unreachable

Three quarters of the runtime dependencies exist only to serve unused components

Once the unimported shadcn files are deleted, 37 of the 51 entries in dependencies have no importer at all: 25 Radix packages plus recharts, embla-carousel-react, cmdk, vaul, react-day-picker, react-hook-form, react-resizable-panels, input-otp and more.

Four are already dead today, before deleting anything: @hookform/resolvers, date-fns, zod, and tailwindcss-animate — the last of which is loaded as a Tailwind plugin but whose animation utilities are never used in any class string.

FixPrune package.json after the component deletion, then regenerate the lockfile. Install size and npm audit surface both drop sharply.

×8 phantom tokens

Tailwind declares eight sidebar-* colours backed by CSS variables that don't exist

tailwind.config.ts maps sidebar, sidebar-foreground, sidebar-primary and five more onto --sidebar-background etc. None of those custom properties is ever defined in src/index.css. Any class using them resolves to an invalid colour.

  • tailwind.config.ts:50–59

FixRemove the sidebar block. Same for the accordion-down / accordion-up keyframes and animations, which only the unused accordion uses.

1 LOC never imported

src/App.css is a file containing the comment /* Reset */

Nothing imports it. main.tsx imports only index.css.

FixDelete.

×2 same cursor

The custom cursor ships as both PNG and SVG; only the PNG is wired up

index.css:42 sets cursor: url('/kickstart_cursor.png'). public/kickstart_cursor.svg is the same mark in a second format and is referenced nowhere. public/placeholder.svg — Lovable scaffolding — is likewise unused.

FixDelete the unused SVGs, or switch the cursor to the SVG and delete the PNG. Do not keep both.

×3 lockfiles

Three package lockfiles, three possible dependency trees

bun.lock (165 KB), bun.lockb (247 KB — the binary form of the same thing) and package-lock.json (238 KB) all sit in the repo root. Whichever one your CI or your teammate's machine happens to honour decides which versions get installed, and nothing keeps the three in step.

FixPick one package manager. Delete the other two lockfiles and add them to .gitignore. If Bun: keep bun.lock, drop the legacy bun.lockb.

×2 same const

×3 same behaviour

"Show all on mobile" is implemented three times from scratch

The same useState + slice(0, n) + toggle-button pattern appears in AlumniGrid.tsx:112 (slice 3), Backers.tsx:43 (slice 3) and Fellows.tsx:200 (slice 6). The three even disagree on the copy — two say "Show less" on collapse, Fellows offers no way back.

×3 double render

Three components render every card into the DOM twice and hide one copy with CSS

On a desktop load, Fellows mounts 28 motion.div cards to show 14; AlumniGrid mounts 30 flip cards to show 21, each with its own logo <img>. Hidden images are still fetched.

FixRender the list once and vary only the grid classes, or gate the slice on a breakpoint value rather than duplicating the tree.

×11 two eyebrow styles

The section eyebrow exists in two competing forms, eleven times

The home page uses a sans variant — text-xs uppercase tracking-[0.2em] text-primary mb-3 font-medium — five times (Philosophy, WhatYouGet, AlumniGrid, Backers, Partners). The sub-pages use a mono variant with different spacing six times (Apply, Fellows, and four separate places in Perks). Apply even wraps its version in a local <Eyebrow> component that the other pages don't import.

FixPromote Apply's <Eyebrow> to src/components/, give it a variant prop if both looks are wanted, and use it in all eleven places.

×4 / ×3 / ×2 class strings

Heading, lede and CTA-button class strings are repeated verbatim

×3 view shells

×27 inline fonts

The two typefaces are re-declared inline 27 times, on top of the global CSS

index.css already sets IBM Plex Sans on body and on h1–h6, and IBM Plex Mono on .font-mono. Despite that, style={{ fontFamily: "'IBM Plex Sans', sans-serif" }} is written out 12 times across 10 components, and the Mono equivalent 15 times across the three pages.   • Mono ×15 — Apply ×6, Fellows ×8, Perks ×1

FixAdd fontFamily.sans and fontFamily.mono to the Tailwind theme, then use font-sans / font-mono classes and delete all 27 inline styles. Changing the brand typeface becomes a one-line edit instead of a 27-file sweep.

×3 one colour

The page background colour is expressed three different ways

index.html hard-codes #0a0a0a on <html> and again on <body>; index.css defines the same colour again as the token --background: 0 0% 4%. They agree today by coincidence of rounding; retheming the site means remembering that two of the three live in a file Tailwind never touches. Separately, AlumniGrid hard-codes hsl(0 0% 5%) twice as its card background instead of using bg-card — and --card is 7%, so the alumni cards are quietly a different shade from every other card in the design system.

FixKeep one inline hex in index.html (it must work before CSS loads), drop the duplicate on <html> or <body>, and comment it as mirroring --background. Replace AlumniGrid's literals with bg-card and decide which shade is correct.

×3 meta tags

<title>, og:title and twitter:title carry the same string; <meta name="description">, og:description and twitter:description carry another. There is also an og:image pointing at a gpt-engineer-file-uploads bucket rather than an asset in this repo, and two stray blank lines where tags were removed.

FixLow stakes — but if the copy changes, all three must change together. Worth a comment marking them as a set, and worth moving the OG image into public/.

Duplication in the Supabase migrations

4 findings

Seven migrations, all dated the same day, iterating on one question: is this user allowed to see perks? Each attempt was left in place, so the answer is now encoded in the database three times over — and the abandoned attempts are still live objects.

×3 same function

is_on_perks_allowlist() is defined three times, with different semantics each time

…092632 creates it as SECURITY DEFINER joining auth.users on a citext cast. …094516 replaces it with the same join but a lower() comparison. …094611 replaces it again as SECURITY INVOKER reading the allowlist directly off the JWT claim. Only the last one runs — the first two are pure history, but a reader has to open all three to know that.

FixLeave shipped migrations alone (rewriting applied history is worse), but add a short supabase/README.md stating which definition is current. Squash before the next environment is provisioned.

×2 dead function

has_perks_access(uuid) is defined twice and is now dead, but still exists in the database

Created in …075121, redefined in …075214, and orphaned by …094803 when the perks RLS policy was rewritten to inline the check instead. The final migration revokes execute on it from every role but never drops it — so a SECURITY DEFINER function that reads auth.users is still sitting in the public schema with no caller.

FixAdd a migration with drop function if exists public.has_perks_access(uuid);. An unused SECURITY DEFINER function is the kind of thing you want gone rather than merely un-granted.

×3 same predicate

The allowlist test is written out in three separate objects

lower(a.email::text) = lower(auth.jwt() ->> 'email') appears in the is_on_perks_allowlist() body, in the "Users can verify their own allowlist row" policy, and again in the "Approved users can view perks" policy. Three copies of one authorisation rule: change the matching semantics — trimming whitespace, say — and missing one copy means the RPC and the row policy disagree about who is allowed in.

  • …094611 (fn + allowlist policy)
  • …094803 (perks policy)

FixHave both policies call public.is_on_perks_allowlist() so the predicate lives in exactly one place.

×4 grant blocks

The same three-line REVOKE incantation is repeated in four migrations

revoke execute … from public / anon / authenticated is re-issued in …075151, …075214, …094516 and …094803 — mostly re-revoking what was already revoked, because each create or replace resets the grants and nobody was certain which state they were in.

FixSymptom of the churn above; resolves when the function definitions are squashed to one.

Configuration written twice

×2 build config

vite.config.ts and vitest.config.ts restate the same plugin and alias setup

Both declare plugins: [react()] and both resolve "@" → ./src. The Vitest config silently misses Vite's dedupe list and the componentTagger plugin, so tests run against a slightly different module graph than the app does.

FixDelete vitest.config.ts and move the test block into vite.config.ts (Vitest reads it natively), or use mergeConfig to extend the real config rather than restating it.

×3 tsconfigs

Three tsconfigs repeat the same compiler options instead of extending one base

paths, skipLibCheck, noImplicitAny: false, noUnusedLocals: false and noUnusedParameters: false are written into both tsconfig.json and tsconfig.app.json; the bundler-mode block (moduleResolution, isolatedModules, allowImportingTsExtensions, moduleDetection, noEmit) is repeated in tsconfig.app.json and tsconfig.node.json. The two also disagree on strict — false for app code, true for config files.

FixPut the shared options in tsconfig.base.json and have both project configs extends it.

FixA src/content/facts.ts exporting EQUITY_TAKEN, AVG_AGE, ACCEPTANCE_RATE, COHORT, and deriving fellow and perk counts from the arrays themselves. Cohort rollover then becomes one edit rather than a hunt.

×4 disagreeing

The partner and mentor roster exists in four versions that don't match

Partners.tsx lists 8 logos. Backers.tsx lists 10 people whose companies partly overlap (Sequoia Capital, 1517 Fund) and partly don't (OakNorth, Octopus Energy, J.P. Morgan, Monzo, Wise, OpenAI). Apply.tsx:32 then names a fifth set in prose — "Sequoia, OakNorth, Octopus, J.P. Morgan, 1517 Fund, Antler" — where Antler appears nowhere else in the site. And AlumniGrid uses "Techstars" and "YC-backed" as company badges, a sixth place the same names are typed.

All ten linkedin fields in Backers.tsx are the placeholder "#", so every card links to the top of the page.

FixOne src/content/network.ts with a typed list of organisations and people, tagged by relationship (partner / mentor / investor). Every surface reads from it, and the Apply prose is generated from the same list.

×2 two spellings

AlumniGrid.tsx:53 lists "InX Tech" — "Industrial X-ray technology". Fellows.tsx:35 describes Aryan Shah building "InxTech" — "autonomous underwater vehicles for offshore energy inspection". Same company, two names, and two descriptions that don't obviously describe the same business. A visitor moving between the two pages sees a contradiction.

FixDecide the canonical name and description, put the company in one companies.ts, and have the fellow record reference it by id.

×3 copy echo

Repeated phrasing inside the copy itself

Philosophy.tsx opens its pull-quote with "Most talented people never compound." and then opens the very next paragraph with "Most talented people scatter their energy…" — the echo reads as an editing artefact rather than a rhetorical device. "Building in frontier tech" appears three times across Apply and Fellows. Partners.tsx also hand-writes its eight partner names into three shuffled arrays (row1, row2, row3) and then triples each row at render time — 8 real partners become 72 DOM nodes and 72 image references.

FixFor Partners: keep one array and shuffle it with a seeded helper per row. For the copy: a light editorial pass, ideally by whoever owns the voice.
